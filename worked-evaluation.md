# When an AI assistant audits a public melanoma RNA-seq dataset

**Case study, 2 October 2026.** This evaluates an AI-generated analysis plan. The [source and provenance review](./audit/publication-readiness-2026-10-02.md) records the pre-run reference chronology and the specimen and timing questions that remain after checking Supplementary Data 1. The linked execution transcript is a path-redacted public copy; the original is retained privately.

## Case and source

I tested whether Claude Code could reason from a public metastatic melanoma count matrix and sample annotations to a defensible analysis of response to immune checkpoint blockade (ICB). The source was [GEO GSE168204](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE168204), specifically `GSE168204_MGH_counts.csv.gz` and parsed GEO sample metadata. The compressed count-file SHA-256 was `4e3ec53c42b7c487a746201eef1cb546d61bede8faedaf9137e3d4ae39cd38ff`. The candidate's workspace initially contained only the count file, `sample_metadata_raw.csv` and `PROMPT.txt`, as confirmed by the first command in the [path-redacted public execution transcript](./claude-code-stage/claude-code-full-execution-transcript1-public.txt).

The case asks for judgment before gene testing. There are 27 GEO samples, but the CSV is two tables placed side by side: 26 MGH count columns are keyed by `Gene`, while the final sample `148-12-13-14_S10` is keyed by another `gene` column. The keys disagree by row in 74,691 of 75,253 rows. Treating the last sample as if it shared the first key would assign counts to wrong genes. The 26-column MGH block has 10 PRE biopsies from 10 provisional patients and 16 ON biopsies from nine patients. Outcomes, batch, regimen and timing are unevenly distributed. The independently prepared [mapping audit](./reference/mapping_audit.md) and [curated sample map](./reference/sample_metadata_curated.csv) document the reference evidence. They were held outside the candidate workspace.

## Prompt and reference

The exact candidate prompt was:

> You have the public GEO GSE168204 count file and sample annotations. Assess whether this dataset supports an analysis of tumour gene expression associated with immune checkpoint blockade response, and whether any finding can be called a pretreatment predictive biomarker. Audit the count header, gene keys and sample-to-GSM mapping before calculations. Identify the patient and biopsy units, repeated observations, treatment timing and regimen, and response overlap across batch and platform. Give the eligible samples, a reproducible analysis plan, model/design checks, QC, multiple-testing and sensitivity checks. You may run justified calculations, but distinguish actual outputs from proposed work and state where you would stop. Do not invent gene-level results or clinical validation.

Run 1 used **Claude Code v2.1.285 with Opus 5.5**, completing at approximately 23:34 BST on 1 October 2026. Its environment reported Python 3.10.11, pandas 2.2.2, NumPy 1.26.4 and SciPy 1.13.1. Rscript and statsmodels were unavailable. The eight-item [reference rubric](./reference/evaluation_handoff.md) scored mapping, units, comparison, clinical descriptors, method, QC/multiplicity, interpretation and reproducibility from 0 to 2, with separate critical failure flags. The reference files have recorded creation times before the run, but **a pre-run Git commit or signed snapshot of the exact Windows-side files has not been supplied**.

## What Claude did

Claude identified the second gene key, demonstrated that `ACTB` for sample 148 would be 8,340 with the correct key but zero under a naive row join, and mapped all 27 count columns to GEO records. It recognised repeated biopsies, including seven samples from patient IPIPD1001. It proposed an eight-person pretreatment core (four responders, four nonresponders) after flagging a PRE biopsy with day +21 and another at day −433. It observed that treatment labels mix anti-PD1, anti-PDL1 and anti-PD1 plus anti-CTLA4. The response stopped before gene-level tests and explicitly rejected a clinical biomarker claim.

The first answer received **12/16**: mapping 2, units 1, comparison 1, clinical descriptors 2, method 2, QC/multiplicity 1, interpretation 2 and reproducibility 1. No defined critical failure flag was established. The [evidence-linked scorecard](./audit/claude-session1-scorecard.md) explains each mark. This score describes one answer under this rubric; it is not a measure of general model accuracy.

Three errors or gaps matter most. First, Claude inferred from high expression correlation that same-day samples were separate specimens or tumour regions rather than technical replicates. Correlation does not establish specimen relationships. Supplementary Data 1 confirms repeated patient/timepoint records but has no GSM or biopsy-site key, so their exact relationships remain unresolved.

Second, it computed the PRE response-by-batch table but did not report the ON table or execute the model-rank check requested in the prompt. In the 26-sample ON subset, only batch 4 contains both outcomes: one R and three NR biopsies. A `~ batch + response` design is mathematically full rank (5/5), yet its adjusted contrast has scant within-batch support. Adding platform makes the model rank deficient (5/6), because platform is determined by batch here. An estimable coefficient would still be fragile biological evidence.

Third, Claude said that with four versus four patients no gene could pass either Bonferroni **or BH** correction across about 15,000 exact rank tests. The minimum two-sided p-value, 2/70 ≈ 0.0286, rules out Bonferroni significance at that test count. It does **not** alone rule out BH, whose threshold depends on the ordered set of p-values ([R `p.adjust` documentation](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/p.adjust.html)). In the proposed core, preserving response counts within batches permits only six label allocations, not the 70 unrestricted allocations quoted for a four-versus-four split. Claude's power numbers were illustrative independent-sample calculations, not measured power for the confounded RNA-seq design.

## Verification boundary and conclusion

The full transcript preserves the initial file listing, commands, outputs and failures. It reveals that Claude's first attempt to check every count's integer format crashed on a blank-column name. After its first answer, the user requested that scripts be copied into the project; Claude fixed that error and reran six scripts. The later check passed, but it must remain a **follow-up repair**, not a verification credited to the first answer. The revised scripts and logs were reviewed separately and are not included in this public folder. No gene-level differential expression, classifier or signature score was run.

This run demonstrates useful AI assistance at the data-audit stage: it detected a dangerous join, counted biological units and stopped short of an unjustified biomarker claim. It also shows why an expert reference and transparent execution record are necessary. The strongest deliverable is the audited decision to limit inference, alongside specific corrections to statistical and specimen-level claims. Any later analysis of published scores should be a separately dated run with its own frozen hypotheses and scoring.
